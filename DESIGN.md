# Design
Operate mode: an analytical workspace with a quiet native sidebar and a large data/result surface. The brief pins the visual direction; no replacement identity is invented.
SF system typography, native source list selection, black/white/semantic secondary labels; restrained rules and generous section separation. Tabular figures for numeric results. Dense data remains legible in a native paged NSTableView; headers sort at the database. Inspector-like profiles retain context. Project/version controls are always visible. Findings have explicit counts, labels and evidence, never color alone. No decorative animation or custom Liquid Glass; native interactions and immediate keyboard feedback.
The welcome screen pairs the authored seal with project creation/open actions. Settings and author credit occupy the sidebar footer. Empty/error/loading/cancel states use actual application state. Chart marks use accessible labels and shapes as well as semantic contrast.

The author subsequently requested richer chart forms and editable colors. The application identity remains monochrome while analytical marks can use six palettes or a custom RGB color, with labels/shape controls independent of color. The workflow draws actual committed provenance; it avoids exposing a large node catalog. PDF layout is neutral A4 with real pagination and readable metric names.


## Integrated canvas

Use the accepted CanvasPrototype topology for the actual application. Dense options live in the selected box’s inspector; the toolbar stays at seven understandable families. The main canvas is the place to compose the process. Node previews use real row counts, summaries and histogram data. New nodes keep the current zoom and focus into view; fit is an explicit action. Color distinguishes operation families and analytical marks, with adaptive text/backgrounds. Bottom data editing uses native table selection and dedicated forms rather than editable-looking static text.
